# Проверка защиты API: HTTP e2e с PostgreSQL

Дата: **30 октября 2026**, 10:48:37–10:48:40 МСК.
Проверенная версия приложения: `c9e9485a285c8c70bef4e76ca02d9b16338e3866`.

## Вывод

**117 тестов прошли, без ошибок и пропусков.** В проверенных сценариях обхода
прав на уровне API не обнаружено. Пользователь только с System получает
успешные ответы System API и отказ Billing; пользователь только с Billing —
успешный ответ Billing и отказ System. Наличие доступа к админке или трекеру
само по себе не даёт доступа к этим API.

Проверены **131 API-запрос**: 24 ответа `200`, 2 ответа `204`, 64 ответа `401`
и 41 ответ `403`. Все коды совпали с ожидаемыми. Во всех **105 отказах** число
вызовов внешнего сервиса было **нулевым**. Проверялся также полезный ответ:
например, Billing возвращал `{"balance":"123.45","currency":"RUB"}`.

## Что именно было реальным

- PostgreSQL **16.4**, доступный на локальном порту `5432`.
- Новая временная база `code_agent_e2e_9abd1b020ade4ec19d45ea6084382f7a`.
  Выполнена настоящая цепочка миграций до `0006`; подтверждены `NOT NULL`
  и `DEFAULT false` у всех пяти полей разрешений.
- Отдельный процесс Uvicorn: PID `72259`. Процесс тестов: PID `72242`.
  Запросы шли по TCP на `http://127.0.0.1:59263`, через HTTPX.
- Приложение загружалось штатной фабрикой `src.main:make_app`, с настоящим
  lifespan, маршрутизацией, JWT-проверкой, репозиториями и SQLAlchemy.
- Bootstrap-администратор создан миграцией. Далее пользователи, права и токены
  создавались и изменялись через штатные HTTP-обработчики `/cadm`.
  Создание токена возвращало его однократное значение; в PostgreSQL отдельно
  проверено хранение SHA-512 хеша, отличного от выданного токена.

Не использовались `TestClient`, ASGI-транспорт внутри процесса, SQLite,
`dependency_overrides`, подмена репозиториев или функций авторизации.
SQL-запросы использовались для подтверждения состояния, а не для выдачи прав
или выпуска токенов.

После завершения процесс приложения остановлен, временная база удалена.
Существующие базы приложения не использовались. Production-код не изменялся.

## Граница e2e

Billing и LLM обращались к локальному HTTP-сервису с контролируемыми ответами.
Поэтому это e2e всей локальной цепочки **HTTP → авторизация → PostgreSQL →
обработчик API → HTTP провайдера → ответ**, но не проверка доступности настоящих
Selectel/OpenAI. Баланс, чат и streaming проходили через реальные сервисные
классы приложения. Offline mode был выключен, кеш баланса отключён.

Провайдерный HTTP-сервис получил 14 запросов за весь прогон. Снимок его счётчика
до и после каждого запрещённого API-запроса подтверждал отсутствие обращения
к провайдеру. Разрешённые запросы с кешированием, например список моделей,
могли не создавать новый upstream-запрос.

UI не тестировался: браузер, отображение страниц, JavaScript и навигация не
проверялись. HTTP-формы админки использованы только как существующий механизм
подготовки пользователей и токенов; отдельного provisioning API в приложении нет.

## Матрица прав

Для каждого профиля создан отдельный пользователь и выпущен отдельный токен.
У обычного пользователя включалась только указанная галочка; остальные были
выключены. У Superuser все галочки выключены, `is_admin=true`.

| Профиль | Health | Info | Billing | Models | Chat | Stream | Cancel |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Без прав | 403 | 403 | 403 | 403 | 403 | 403 | 403 |
| Только System | 200 | 200 | 403 | 403 | 403 | 403 | 403 |
| Только Billing | 403 | 403 | 200 | 403 | 403 | 403 | 403 |
| Только LLM | 403 | 403 | 403 | 200 | 200 | 200 | 200 |
| Только Admin | 403 | 403 | 403 | 403 | 403 | 403 | 403 |
| Только Time Tracking | 403 | 403 | 403 | 403 | 403 | 403 | 403 |
| Superuser | 200 | 200 | 200 | 200 | 200 | 200 | 200 |

Это 49 независимых проверок прав. Chat и Stream — два режима одного POST.
Перед успешной отменой создавался реальный поток через API, чтобы приложение
получило идентификатор completion и сохранило связь с провайдером.

| Операция | Метод и путь |
| --- | --- |
| Health | `GET /api/system/health/` |
| Info | `GET /api/system/info/` |
| Billing | `GET /api/billing/balance/` |
| Models | `GET /api/ai-proxy/models` |
| Chat / Stream | `POST /api/ai-proxy/chat/completions`, `stream=false/true` |
| Cancel | `DELETE /api/ai-proxy/chat/completions/chatcmpl-e2e` |

## Невалидная аутентификация

Каждый вариант проверен на всех семи операциях выше: **63 проверки**, везде
получен `401`, обращений к провайдеру нет.

| Состояние | Как проверено |
| --- | --- |
| Нет заголовка | `Authorization` отсутствует |
| Пустой заголовок | `Authorization: ""` |
| Нет токена после схемы | `Authorization: Bearer` |
| Неверный формат | строка `not-a-token` |
| Изменена подпись | изменён символ подписи настоящего токена |
| Истёкший токен | токен штатно выпущен с датой истечения в 2020 году |
| Отключённый токен | штатное действие deactivate после выдачи токена |
| Удалённый токен | сохранённый клиентом токен удалён через HTTP |
| Неактивный superuser | пользователь отключён; `is_admin=true` не помог |

В первой итерации тестовый HTTP-клиент отказался отправлять `Bearer ` с
пробелом в конце. Сценарий исправлен на допустимый HTTP-заголовок `Bearer`,
который действительно дошёл до приложения и получил `401`. Это было
ограничение тестового клиента; итоговые артефакты содержат успешный прогон.

## Изменения прав с уже выданным токеном

Для одного пользователя использован **один и тот же токен** во всех шагах.
Права менялись через HTTP-редактирование пользователя и подтверждались в БД.

| Шаг | Состояние | System Health | Billing |
| --- | --- | --- | --- |
| 1 | Только System | 200 | 403 |
| 2 | System + Billing | 200 | 200 |
| 3 | Только Billing | 403 | 200 |
| 4 | Все права сняты | 403 | 403 |
| 5 | `is_admin=true`, галочки выключены | 200 | 200 |
| 6 | `is_admin=false`, галочки выключены | 403 | 403 |

Перевыпуск токена не требовался; отдельно подтверждено, что у пользователя
остался ровно один токен. Это подтверждает загрузку актуальных прав из БД.

Дополнительно выполнен цикл с другим токеном: `200` → отключение токена →
`401` → включение токена → `200`. Оба LLM OPTIONS-запроса без токена вернули
пустой `204`, не обратившись к провайдеру; feature-данные через preflight не
выдаются.

## Ограничения вывода

Проверялась защита текущих API-операций, а не полный аудит безопасности.
Не проверялись реальные Selectel IAM и провайдерные аккаунты, TLS, Nginx,
сетевые ACL, нагрузка, гонки при одновременном изменении прав и JWT-алгоритмы
за пределами штатной конфигурации HS256. У Time Tracking сейчас нет отдельных
проверяемых API-операций: его профиль проверен на отсутствие доступа к чужим
API; HTML-маршруты трекера исключены по запросу.
